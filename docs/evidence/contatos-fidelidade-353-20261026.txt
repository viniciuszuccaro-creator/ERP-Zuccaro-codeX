Contatos[] ↔ escalares MASTER — fidelidade (2026-10-26)
=======================================================
Tip candidata pós-remarge d86f06b6 · runner Cursor

Problema
- Contrato HTTP/PG Cliente MASTER = email / telefone / celular.
- UI Base44 = contatos[] com nome, tipo, valor, principal, observação (+ id/ordem).
- Projeção silenciosa descartava múltiplos do mesmo tipo e metadados.
- Hidratar contatos[] a partir de escalares fingia lista completa na reabertura.

Correção (isolada, sem migration)
- assessContatosScalarFidelity: ok só com ≤1 valor/canal e sem nome/obs/id/ordem.
- applyContatosProjection: se !ok → CONTATOS_SCALAR_OVERFLOW (422), sem fetch.
- withHydratedContatos: NÃO injeta contatos[]; anexa contatos_escalares
  { source:'scalars', complete:false, items[] }.
- Preserva contatos[] se o transporte já trouxer (Base44).

Provas: tests/cliente-contatos-http-adapter.test.js

  schema strict allowlist + auditoria), reutilizando o array UI.
