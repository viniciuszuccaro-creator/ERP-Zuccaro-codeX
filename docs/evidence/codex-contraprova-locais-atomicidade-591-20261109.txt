CONTRATO BFF (explícito)
- CLIENTE_LOCAIS_BATCH_ATOMIC = false
- Cada POST/PATCH/DELETE /clientes/:id/locais é transação própria no server
  (clienteLocalService.withTransaction por operação).

  Cursor NÃO inventa storage paralelo nem ContatoClienteV2.

O QUE ESTE TIP ENTREGA (comportamento suportado e testado)
1) Preflight do lote inteiro (map create/update) → zero writes se inválido/extras.
2) draft === undefined → skip (omissão ≠ lista vazia).
3) baselineIds null/undefined → sem soft-delete.
4) assertScope + clienteId congelado entre awaits (Grupo/Empresa/sessão/ator).
5) Falha remota → CLIENTE_LOCAIS_SYNC_PARTIAL com:
   created/updated/deleted, ops[], reconcileRequired=true, batchAtomic=false.
6) Completo: em PARTIAL, listLocais → reconcilia locaisHttpView + baseline +
   formData.locais_entrega (estado real); toast ≠ sucesso; invalidate queries.
7) Reexecução: draft reconciliado só com ids canônicos → updates idempotentes.
